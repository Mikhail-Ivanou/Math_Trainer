# Math Trainer

Тренажёр примеров для школьника. Начинаем с математики 5 класса.

## Состав

```
math-trainer/
├── backend/   локальный сервер: обработка книг, LLM для сайта, API админки
├── web/       локальный сайт (как приложение) и админка /admin
├── app/       Flutter-приложение (Android, iOS): темы, примеры, отметки, генерация
└── data/      учебники и локальные данные (не в git)
```

## Архитектура

Общая точка — **Firebase** (Firestore + Firebase Auth). Приложение работает
только с Firebase и aiai.by и о нашем сервере не знает. Сайт и админка
запускаются локально, нигде не публикуются и могут быть выключены.

```
 data/*.pdf ──► backend (127.0.0.1:3101) ──► Firestore ◄── app (Android / iOS) ──► aiai.by
                   ▲   │ LLM: ключ бэкенда       ▲
                   │   └─► aiai.by               │
                 web (localhost:3000) ───────────┘
                 сайт + /admin
```

- **backend** разбирает учебники и публикует библиотеку (книги → параграфы →
  правила). Через него сайт обращается к LLM: поиск правила и генерация
  заданий с проверкой ответов. Админка через него управляет книгами,
  параграфами и правилами.
- **web** — те же экраны, что в приложении (вход, темы по классам, добавление
  темы, правило, задания, «решено», «Скрыть решённые», уровень, генерация).
  Данные читает и пишет в Firestore сам, от имени ученика, под теми же
  правилами. Плюс PDF и админка.
- **app** — Flutter-приложение, LLM вызывает напрямую (отдельный ключ с лимитом).

## Сайт и админка (локально)

```bash
cd backend && npm install && npm run server   # http://127.0.0.1:3101
cd web && npm install && npm run dev          # http://localhost:3000
```

`web/.env.local` — конфиг веб-приложения Firebase (пример в `web/.env.example`)
и `NEXT_PUBLIC_BACKEND_URL`. Сервер слушает только 127.0.0.1. Запросы сайта к
LLM проверяют Firebase ID-токен ученика, админка открыта без входа, но только
с этой машины. Генерация и поиск идут ключом бэкенда (`backend/.env`).

**PDF.** На странице темы «Скачать PDF» сохраняет на диск нерешённые задания
темы. В приложении кнопка PDF в заголовке темы открывает системное меню
«Поделиться» (сохранить в «Файлы», отправить, распечатать). В PDF задания с
местом для решения, а на последней странице ответы. Шрифт DejaVu Sans
(кириллица, x², ·, −) лежит в `web/public/fonts` и `app/assets/fonts`.

**Админка** (`/admin`):
- учебники: добавить по id портала adu.by или загрузив PDF. Название,
  предмет, класс, часть, авторов и год LLM читает с титульных страниц и из
  выходных данных книги и составляет из них id (`physics7`, `math5-1`).
  Дальше книга сразу обрабатывается (оглавление, параграфы, листы и правила)
  и публикуется в каталог своего класса. «Обработать» повторяет обработку с
  кэшем LLM, «С нуля» очищает кэш, «Удалить» — с темами учеников или без них.
  Предмет любой: промпты подстраиваются под него. Вне математики задания —
  расчётные задачи с числовым ответом и единицей (их ответ проверяется);
  теоретических вопросов пока нет;
- параграфы: название и лист параграфа, удалить, «Разбить на правила заново»;
- правила: название, формулировка, ключевые слова, удалить, добавить. Правка
  правила попадает и в тему, если ученики её уже добавили;
- «Что вызывает трудности»: темы по числу учеников, что они писали, сколько
  заданий.

После добавления, обработки и правок каталог `catalog/grade-{n}` пересобирается
из Firestore. Новый класс сразу появляется на сайте и в приложении.

Генерация и проверка ответов есть в двух копиях: Dart
(`app/lib/tasks/`) и TypeScript (`backend/src/tasks/`). Промпты и правила
проверки нужно менять в обеих.

## Данные (Firestore)

База `(default)` в `europe-central2`. Правила лежат в
[firebase/firestore.rules](firebase/firestore.rules), их проверяют тесты на эмуляторе.

**Библиотека** — учебники 5–7 классов, разобранные на параграфы, а параграфы — на
отдельные правила («Распределительный закон умножения», «Нахождение процента от
числа»). Её публикует backend, клиенты только читают. **Темы** добавляют сами
ученики: пишут, что даётся трудно, приложение находит конкретное правило в
учебниках своего класса, и оно становится темой. Если тему уже добавил кто-то
другой, ученик присоединяется к ней. Так собирается база правил, которые
вызывают трудности. Внутри темы показывается само правило с примером, а по
кнопке «Весь параграф» — лист всего параграфа.

| Путь | Что | Кто пишет |
|---|---|---|
| `books/{bookId}` | учебник | backend |
| `books/{bookId}/sections/{sectionId}` | параграф: глава, номер, название, `rule` (лист всего параграфа), `keywords` | backend |
| `books/{b}/sections/{s}/rules/{ruleId}` | одно правило параграфа: название, формулировка с примером, ключевые слова | backend |
| `catalog/grade-{n}` | все правила класса одним документом, для поиска темы | backend |
| `topics/{ruleId}` | тема = добавленное учеником правило; поля скопированы из правила | приложение (только создание) |
| `topics/{id}/requests/{uid}` | что написал ученик, добавляя тему | владелец |
| `topics/{id}/tasks/{taskId}` | задания, общие для всех | backend и приложение (только создание) |
| `users/{uid}` | профиль (последний выбранный класс) | владелец |
| `users/{uid}/progress/{topicId}__{taskId}` | отметка «решено» | владелец |

Id темы совпадает с id правила. Поэтому одно и то же правило не станет двумя
темами, а правила Firestore проверяют, что поля темы совпадают с правилом из
учебника.
Задание из приложения принимается только целиком: тип, сложность, текст,
ответ-строка, `source: "app"`, `createdBy` — uid автора, `createdAt` — время
сервера. Менять и удалять темы и задания клиенты не могут.

```bash
cd firebase && npm install
JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home" npm run test:rules
firebase deploy --only firestore:rules,firestore:indexes   # из корня репозитория
```

## Backend

`backend/` собирает библиотеку из PDF в `data/`:

1. текст страниц (pdf-parse), без колонтитулов и водяного знака;
2. оглавление в конце книги разбирает LLM: в PDF оно искажено (разорванные
   номера страниц, оторванные буквы, обрезанные названия). Тесты, «Математика
   вокруг нас», самооценка и повторение отбрасываются;
3. параграфы ищутся в тексте по заголовкам «§ N.» в порядке оглавления (в 6
   классе нумерация начинается заново в каждой главе);
4. для каждого параграфа LLM пишет лист параграфа (определения, правила,
   примеры с решением) и раскладывает параграф на 2–10 отдельных правил:
   название, формулировка с примером, ключевые слова для поиска.

Ответы LLM кэшируются в `data/books/`, повторный запуск бесплатный.

```bash
cd backend && npm install
cp .env.example .env                   # AIAI_API_KEY — ключ бэкенда, не приложения
npm run import:books -- --no-rules     # проверить разбиение
npm run import:books -- --publish      # листы и правила + books/, sections, rules, catalog/ в Firestore
npm run reset:topics -- --yes          # удалить все темы, их задания и отметки
```

Для записи в Firestore нужен ключ сервисного аккаунта: Firebase Console →
Project settings → Service accounts → Generate new private key. Сохранить его
как `backend/service-account.json`, он в .gitignore.

## LLM

Провайдер — [aiai.by](https://aiai.by) (API, совместимый с OpenAI). Модель по
умолчанию — `claude-haiku-5.5`. Её выбрали по сравнению 10 моделей на генерации
заданий по § 8: все ответы верные, задачи самые разнообразные и жизненные,
~13 с на 12 заданий, ~1,3 BYN за 1000 заданий.

LLM в приложении делает две вещи:
- по запросу ученика («распределительный закон», «не понимаю, как складывать
  дроби») находит правила в каталоге его класса
  (`app/lib/topics/topic_matcher.dart`). Выдуманные id отбрасываются, а без
  ключа работает обычный текстовый фильтр;
- генерирует задания именно на правило темы; лист параграфа идёт как фон,
  чтобы задания были по силам ученику этого класса.

Каждое задание приходит с проверяемой формой (`expr`, `equation` или
`solution_expr`). Приложение само вычисляет ответ в точных дробях
(`app/lib/tasks/task_verifier.dart`): целые, десятичные и обыкновенные дроби,
отрицательные числа, переменные и степени. Задания «упростите» проверяются
подстановкой случайных значений в исходное и упрощённое выражения. Задания,
где модель ошиблась или не вписала выражение в текст, отбрасываются.

**Ключ в приложении.** Ключ вшивается в сборку, а из APK его можно достать.
Поэтому в приложении используется **отдельный ключ aiai.by с лимитом расходов**,
а не ключ бэкенда. Если ключ утечёт, его перевыпускают в кабинете aiai.by и
пересобирают приложение. В git ключ не попадает:

```bash
cp app/secrets.example.json app/secrets.json   # вписать AIAI_API_KEY
cd app && flutter run --dart-define-from-file=secrets.json
cd app && flutter build apk --release --dart-define-from-file=secrets.json
```

Проверка на настоящем API (ключ берётся из окружения, в приложение не вшивается):

```bash
cd app && AIAI_API_KEY=... flutter test test/task_generator_test.dart
```

## Мобильное приложение

- Идентификатор: `com.agidel2012.math` (Android `applicationId` и iOS bundle id).
- Распространение: APK для Android, в сторы не публикуем.
- iOS должен полностью работать. Проверяем на симуляторе, подписываем личной
  командой Apple. Команда в проекте не прописана: её выбирают в Xcode
  (Runner → Signing & Capabilities).

```bash
cd app && flutter run --dart-define-from-file=secrets.json
```
